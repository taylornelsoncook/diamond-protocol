API reference

Read athletes, programs and sessions, and send test results from devices and other systems. Base URL: https://your-site/api/v1

Authentication

Create a key in API & integrations. It's shown once. Send it with every request as a bearer token. Revoke a key there at any time; it stops working immediately.

Authorization: Bearer dp_live_…

All requests and responses are JSON (Content-Type: application/json). Use HTTPS in production. Keep keys on your server, never in a web page or app that others can read.

Errors

Errors return a non-2xx status and a plain sentence you can show or log:

HTTP/1.1 401 Unauthorized
{ "error": "That API key is not valid or was revoked." }
StatusMeaning
400Something in the request needs fixing. The error says what.
401Missing, wrong or revoked API key.
404No record with that ID.
500Something went wrong on our side. Try again.

Endpoints

GET/api/v1/athletes

Active athletes, ordered by last name. Every athlete has an Athlete ID (code, like AVALOP2026) that ties results, bookings and sales together.

QueryDescription
qOptional. Match on name or Athlete ID.
limitOptional. 1–500, default 100.
offsetOptional. For paging, default 0.
curl https://your-site/api/v1/athletes?limit=2 \

Sessions (classes, camps, team sessions, privates and evaluations) with how many are booked. Times are local wall-clock time at the facility, YYYY-MM-DDTHH:MM.

POST/api/v1/results

Send test results from a device or another system: one result, or an array of up to 1,000. A result with an Athlete ID goes straight to that athlete's profile. Anything else waits in Waiting to be linked on the dashboard; once staff link a device there with Remember on, its results go straight in from then on.

FieldDescription
athlete_codeThe Athlete ID, like AVALOP2026. Send this, or device_id/device_name.
device_idYour system's ID for the athlete or device, used to remember the link.
device_nameA readable label shown to staff while it waits to be linked, like Chidi O.
sourceRequired. Where it came from, like hawkin, ovr or rapsodo.
testRequired. A test name from the test library, like Vertical jump or CMJ jump height.
valueRequired. A number.
unitOptional. The unit you measured in (for example cm or in); it's converted to the test's unit.
recorded_atOptional. ISO 8601 time it was measured. Default now.
refOptional but recommended. Your unique ID for the result. Sending the same ref twice saves it once.
curl -X POST https://your-site/api/v1/results \
  -H "Authorization: Bearer dp_live_…" \
  -H "Content-Type: application/json" \
  -d '[
    {"athlete_code":"AVALOP2026","source":"hawkin","test":"CMJ jump height","value":41.2,"unit":"cm","ref":"trial-88412"},
    {"device_id":"hk-5521","device_name":"Chidi O","source":"hawkin","test":"CMJ jump height","value":52.9,"unit":"cm","ref":"trial-88413"}
  ]'

{ "ok": true, "saved": 1, "pending": 1, "duplicates": 0, "prs": 0,
  "results": [ { "index": 0, "status": "saved", "id": 812, "pr": false }, { "index": 1, "status": "pending", "id": 17 } ] }

If any result has a problem, nothing is saved and you get every problem at once:

HTTP/1.1 400 Bad Request
{ "error": "Nothing was saved. Fix these results and send them again.",
  "errors": [ { "index": 1, "error": "\"Vert jump\" doesn't match a test in the library." } ] }

Webhooks

Add a webhook in API & integrations with the events you want. When one happens we POST JSON to your URL straight away. Answer with any 2xx status within 8 seconds. Every delivery and its status is listed under the webhook; use Send test event to try your endpoint (it sends test.ping).

POST /your/hook
Content-Type: application/json
x-dp-signature: 5f1c0d…e93a

{
  "event": "workout.completed",
  "created_at": "2026-09-26T23:12:04.118Z",
  "data": {
    "athlete_code": "AVALOP2026", "athlete": "Ava Lopez", "program": "Youth Speed Foundations",
    "week": 2, "day": 2, "title": "Strength", "exercises_done": 4, "exercises_total": 4,
    "note": "Felt strong today.", "finished_at": "2026-09-26 23:12:04"
  }
}

Verify signatures

x-dp-signature is the hex HMAC-SHA256 of the raw request body, keyed with the webhook's signing secret (shown once when you add it, starting whsec_). Compute it over the exact bytes you received, before parsing the JSON, and compare in constant time. Reject the request if it doesn't match.

Node.js (Express)

const crypto = require('crypto');
app.post('/hooks/dp', express.raw({ type: 'application/json' }), (req, res) => {
  const expected = crypto.createHmac('sha256', process.env.DP_WEBHOOK_SECRET).update(req.body).digest('hex');
  const got = String(req.get('x-dp-signature') || '');
  if (got.length !== expected.length || !crypto.timingSafeEqual(Buffer.from(got), Buffer.from(expected))) return res.sendStatus(401);
  const { event, data } = JSON.parse(req.body);
  // handle event…
  res.sendStatus(200);
});

Python

import hmac, hashlib
def is_valid(raw_body: bytes, signature: str, secret: str) -> bool:
    expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature or "")

Deliveries aren't retried automatically, and the same event can in rare cases arrive twice, so make your handler safe to run twice.
