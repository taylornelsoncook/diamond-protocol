API reference

Read athletes, results, programs, sessions and CRM leads, send test results from devices and other systems, and add leads from your own forms. Base URL: https://your-site/api/v1

Authentication

Create a key in API & integrations. It's shown once. Send it with every request as a bearer token. Revoke a key there at any time; it stops working immediately.

Authorization: Bearer dp_live_…

All requests and responses are JSON (Content-Type: application/json). Use HTTPS in production. Keep keys on your server, never in a web page or app that others can read.

Every request made with a key is listed under that key (Requests) for 30 days, with the answer it got, so you can see what another system is doing.

Access levels

Each key has one of two access levels, chosen when you create it and changeable later:

LevelCan do
Read onlyEvery GET endpoint: athletes, results, tests, programs and sessions. Best for spreadsheets and dashboards.
Read and send resultsEverything above, plus POST /api/v1/results.

A read-only key that tries to send data gets 403.

Errors

Errors return a non-2xx status and a plain sentence you can show or log:

HTTP/1.1 401 Unauthorized
{ "error": "That API key is not valid or was revoked." }
StatusMeaning
400Something in the request needs fixing. The error says what.
401Missing, wrong or revoked API key.
403The key is read-only and the request tries to send data.
404No record with that ID.
500Something went wrong on our side. Try again.

POST/api/v1/results

Needs a key that can read and send results. Send test results from a device or another system: one result, or an array of up to 1,000. A result with an Athlete ID goes straight to that athlete's profile. Anything else waits in Waiting to be linked on the dashboard; once staff link a device there with Remember on, its results go straight in from then on.

FieldDescription
athlete_codeThe Athlete ID, like AVALOP2026. Send this, or device_id/device_name.
device_idYour system's ID for the athlete or device, used to remember the link.
device_nameA readable label shown to staff while it waits to be linked, like Chidi O.
sourceRequired. Where it came from, like hawkin, ovr or rapsodo.
testRequired. A test name from the test library, like Vertical jump or CMJ jump height.
valueRequired. A number.
unitOptional. The unit you measured in (for example cm or in); it's converted to the test's unit.
recorded_atOptional. ISO 8601 time it was measured. Default now.
refOptional but recommended. Your unique ID for the result. Sending the same ref twice saves it once.
curl -X POST https://your-site/api/v1/results \
  -H "Authorization: Bearer dp_live_…" \
  -H "Content-Type: application/json" \
  -d '[
    {"athlete_code":"AVALOP2026","source":"hawkin","test":"CMJ jump height","value":41.2,"unit":"cm","ref":"trial-88412"},
    {"device_id":"hk-5521","device_name":"Chidi O","source":"hawkin","test":"CMJ jump height","value":52.9,"unit":"cm","ref":"trial-88413"}
  ]'

{ "ok": true, "saved": 1, "pending": 1, "duplicates": 0, "prs": 0,
  "results": [ { "index": 0, "status": "saved", "id": 812, "pr": false }, { "index": 1, "status": "pending", "id": 17 } ] }

If any result has a problem, nothing is saved and you get every problem at once:

HTTP/1.1 400 Bad Request

  "errors": [ { "index": 1, "error": "\"Vert jump\" doesn't match a test in the library." } ] }

No API key? The public form endpoint POST /api/public/enquiry takes parent_name, email, phone, athlete_name, athlete_age, grad_year, sport, interest, message and sms_opt_in, and emails the owners. It's rate limited, and a filled-in website field is treated as spam.

Webhooks

Add a webhook in API & integrations with the events you want. When one happens we POST JSON to your URL straight away. Answer with any 2xx status within 8 seconds. Every delivery is listed under the webhook with what we sent and what your server answered.

Send test event sends test.ping, or a realistic sample of any event you subscribe to, with "test": true in its data, so you can build and check your handler before real events arrive.

HeaderDescription
x-dp-signatureHex HMAC-SHA256 of the raw body with your signing secret. See Verify signatures.
x-dp-eventThe event name, like booking.created.
x-dp-deliveryThe delivery ID. It stays the same when a delivery is retried or resent, so use it to ignore repeats.
user-agentDiamondProtocol-Webhooks/1.0
POST /your/hook
Content-Type: application/json
x-dp-signature: 5f1c0d…e93a

x-dp-delivery: 4821

Retries

If your server doesn't answer with a 2xx (or doesn't answer within 8 seconds), we try the same delivery again after 5 minutes, 30 minutes and 2 hours: four tries in all, within a day of the event. Retries wait while a webhook is paused. Redirects count as failures, so give the final URL.

You can also resend any delivery by hand, or resend every failed delivery from the last 7 days at once after fixing your server. A resend carries the same body and x-dp-delivery, signed with the current secret.

If you need a new signing secret, use New signing secret on the webhook. The old secret stops being used straight away.

Verify signatures

x-dp-signature is the hex HMAC-SHA256 of the raw request body, keyed with the webhook's signing secret (shown once when you add it, starting whsec_). Compute it over the exact bytes you received, before parsing the JSON, and compare in constant time. Reject the request if it doesn't match.

Node.js (Express)

const crypto = require('crypto');
app.post('/hooks/dp', express.raw({ type: 'application/json' }), (req, res) => {
  const expected = crypto.createHmac('sha256', process.env.DP_WEBHOOK_SECRET).update(req.body).digest('hex');
  const got = String(req.get('x-dp-signature') || '');
  if (got.length !== expected.length || !crypto.timingSafeEqual(Buffer.from(got), Buffer.from(expected))) return res.sendStatus(401);
  const { event, data } = JSON.parse(req.body);
  // handle event…
  res.sendStatus(200);
});

Python

import hmac, hashlib
def is_valid(raw_body: bytes, signature: str, secret: str) -> bool:
    expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature or "")

Because of retries and resends the same delivery can arrive more than once. Keep the x-dp-delivery IDs you've handled and skip repeats, or make your handler safe to run twice.
